범위·판정·산정 방법

재현 가능한 데이터와 스크립트 포함

무엇을 구현으로 인정했는가

  • 대상: 제공 ZIP의 ddr5_device.sv(1,696줄) 및 실제 호출·참조하는 ddr5_pkg.sv, ddr5_timing_pkg.sv, ddr5_ecc_pkg.sv. 같은 ZIP의 controller/PHY에 있는 기능은 이 DUT의 구현으로 인정하지 않았습니다.
  • F: 문장에 명시된 동작·조건에 대응하는 구현을 확인. 인접 문장의 다른 요구나 기능 전체의 통과를 뜻하지 않습니다. 대부분 정적 근거이며 일부만 실행 근거가 있습니다.
  • P: 동작의 일부는 있으나 문장의 조건을 모두 충족하지 못함. N: 필요한 실행 경로·상태·검사가 없음. X: 문장과 모순되는 값·순서·동작을 확인.
  • U: 문맥·문서 표현·fault boundary·추가 검증 부족으로 확정하지 못함. 미구현으로 단정하지 않고 전체 분모에는 남깁니다.
  • S: digital SV로 구현 가능한 host/controller, 다중 rank/channel 또는 testbench 항목. 이 단일 DUT에서는 구현되지 않았습니다. 전체 digital 분모에 포함하고 device-local 집계에서는 분리합니다.
  • E: 순수 전압·전류·저항·물리 패키지·전기 측정 정확도, 참조·정의·허용 사항·서식 등. ODT/DFE 등의 디지털 제어·상태와 command timing은 포함하고 실제 analog 품질만 구분합니다.

어떻게 계산하고 검토했는가

  • 확인률 = F ÷ (F+P+N+X+U+S) × 100. P를 임의의 0.5점으로 환산하지 않았습니다. 동일 기능의 반복 문장도 등장 위치별로 집계하므로 기능 중요도·개발 공수 비율과 다릅니다.
  • optional/BL32/3DS/다른 밀도·속도도 사용자의 넓은 범위 요청에 맞춰 포함했습니다. “기본 x16/4800B 구성에서 안 쓰는 기능”이라는 이유로 제거하지 않았습니다. 특정 구성에 한정된 문장은 해당 조건을 판정 사유에 표시합니다.
  • PDF 502페이지의 native text·bookmark·표 좌표를 추출하고, 절과 문장을 연결했습니다. 코드 전체 및 직접 package를 읽고 기능별 근거를 구성한 뒤 명시적 문장 규칙, 절별 부재 규칙, 개별 재검토로 판정을 만들었습니다. 모든 항목을 독립적으로 실행 검증한 것은 아닙니다.
  • 표 행·수식·그림 라벨은 문장과 중복 가중하지 않도록 별도 목록입니다. 표 행의 보류는 수치·열 대응을 추가 확인해야 한다는 뜻입니다.
  • 자동 추출에는 페이지/블록 간 분리·결합, 수식의 마침표, 다중 열/병합 표의 읽기 순서 오류 가능성이 있습니다. 일부에는 경계 경고를 표시했습니다. 원문 텍스트·제목·PDF를 함께 제공하므로 원문 기준 재검토가 가능합니다.
  • 남은 검증: 판정 보류의 write recovery와 vendor fault boundary, 세부 timing 수치/표, 전체 pin-level command 조합·동시성·parameter matrix. 따라서 확정된 전 규격 구현률이나 sign-off 보고서로 사용할 수 없습니다.
